# atmolit — STM32F103 (Blue Pill) + ST7789 240x280 + SCD41, FreeRTOS

Прошивка для Blue Pill: дисплей ST7789V3 240×280 по SPI, датчик CO₂ SCD41 по I2C,
две задачи FreeRTOS, вывод на экран и в UART.

> **Важно про чип.** Плата продаётся как F103C8T6, но по факту на ней часто стоит
> кристалл **C6**: `DBGMCU_IDCODE = 0x10006412` (dev ID 0x412), 32 КБ flash и 10 КБ SRAM
> вместо 64/20. Проверяется по регистру `0x1FFFF7E0` (размер flash) и границе RAM.
> Поэтому в `platformio.ini` выбран `board = bluepill_f103c6`. Если у вас настоящий C8 —
> верните `bluepill_f103c8` и можно увеличить `LCD_BAND_LINES` и `configTOTAL_HEAP_SIZE`.

```
atmolit/
├── platformio.ini
├── include/
│   ├── board.h          # ← вся распиновка и параметры панели
│   ├── FreeRTOSConfig.h
│   ├── font8x8.h        # шрифт 8×8, public domain
│   ├── lcd_st7789.h
│   └── scd41.h
└── src/
    ├── main.c           # HAL init, задачи, отрисовка
    ├── lcd_st7789.c     # SPI-драйвер панели
    ├── scd41.c          # I2C-драйвер датчика (CRC-8)
    ├── timebase.c       # HAL-тик на TIM4 (SysTick занят FreeRTOS)
    └── freertos/        # kernel 11.1.0 + порт ARM_CM3 + heap_4
```

## Подключение

### Дисплей ST7789V3 240×280 (SPI1)

| Дисплей | STM32F103 | Примечание |
|---|---|---|
| VCC | **3.3 V** | 5 В только если на модуле есть LDO |
| GND | GND | |
| SCL / SCK | **PA5** | SPI1_SCK |
| SDA / MOSI / DIN | **PA7** | SPI1_MOSI |
| CS | **PA4** | программный CS |
| DC / RS | **PA3** | |
| RES / RST | **PA2** | |
| BL / LED | **3.3 V** | подсветка 60–100 мА, GPIO её не тянет |
| MISO | — | не подключать |
| TE | — | не подключать |

SPI1 на **36 МГц** (APB2 72 МГц / 2) с блокирующими передачами. DMA-путь реализован,
но на этой панели/проводах через некоторое время залипает (36, 18 и 9 МГц), поэтому
по умолчанию выключен: `LCD_USE_DMA 0` в `board.h`. Кадр 240×280×2 = 131 КБ
не влезает в 10 КБ SRAM, поэтому кадр рисуется полосами по 4 строки (1920 байт).

### Датчик SCD41 (I2C1)

| SCD41 | STM32F103 | Примечание |
|---|---|---|
| VDD / VIN | **3.3 V** | средний ток ~15 мА + импульсные пики |
| GND | GND | |
| SCL | **PB6** | I2C1_SCL, 100 кГц |
| SDA | **PB7** | I2C1_SDA |
| SEL (если есть) | GND | |

Если модуль без подтяжек — добавьте **4.7 кОм** с SDA и SCL на 3.3 В.
Конденсатор 100 нФ + 1 мкФ у датчика не помешает.

### UART-консоль (логи, 115200 8N1)

| STM32 | USB-UART |
|---|---|
| PA9 (USART1_TX) | RX |
| PA10 (USART1_RX) | TX |
| GND | GND |

### Прошивка через ST-Link

| ST-Link | Blue Pill |
|---|---|
| SWDIO | PA13 |
| SWCLK | PA14 |
| GND | GND |
| 3.3V | 3.3V (или питать плату отдельно) |

## Сборка и прошивка

```bash
pip install platformio          # если ещё не стоит

pio run                         # сборка
pio run -t upload               # прошивка через ST-Link
pio device monitor              # консоль, 115200
```

Или через UART-бутлоадер (без ST-Link):

1. `BOOT0 = 1`, `BOOT1 = 0`, нажать Reset;
2. `stm32flash -w .pio/build/bluepill_f103c8/firmware.bin -v -g 0x0 /dev/ttyUSB0`;
3. `BOOT0 = 0`, нажать Reset.

## Экран

Портретный дашборд 240×280:

- заголовок `AIR MONITOR`;
- крупное значение CO₂ (шрифт 8×8, увеличение ×5) и `ppm`;
- статус `GOOD` / `FAIR` / `POOR` / `VENTILATE` с цветом по порогам 800 / 1200 / 2000 ppm;
- шкала качества 400–2000 ppm с зелёной, жёлтой и оранжевой зонами и белым маркером;
- две карточки: `TEMP` и `HUM` (целая часть крупно, десятая — мелко);
- график CO₂ за последние 4 минуты: 48 отсчётов по 5 с, заливка, линия по цвету
  текущего уровня, сетка на 800/1200 ppm, подписи оси Y (400/800/1200/2000 ppm)
  и оси X (−4м / −2м / сейчас). Пока данных меньше 4 минут, линия растёт справа;
- при отсутствии датчика вместо значений выводится `NO DATA`;
- в правом верхнем углу — зелёная точка, мигает 1 Гц: индикатор живости между замерами.

Кадр перерисовывается целиком только при новых данных (раз в 5 с), поэтому CPU почти всё
время свободен для задачи датчика.

## Что внутри

| Задача | Приоритет | Стек | Работа |
|---|---|---|---|
| `lcd` | 2 | 1.25 КБ | инициализация панели, отрисовка дашборда по флагу `g_ui_dirty`, heartbeat на PC13 |
| `scd` | 3 | 1.5 КБ | поиск датчика, серийник, старт измерений, чтение раз в 5 с |
| `sup` | 1 | 1 КБ | watchdog: кормит IWDG только пока живы обе задачи; печатает статус раз в 10 с |
| `IDLE` | 0 | 512 Б | FreeRTOS |

- **IWDG** (~4 с по LSI/64) кормит только задача `sup`. Она раз в секунду проверяет,
  что счётчик отрисовки `g_lcd_bands` растёт, а датчик опрашивается; если датчик найден,
  но 60 с нет свежих данных — кормление прекращается и МК перезагружается. После трёх
  неудачных чтений подряд I2C переинициализируется. При остановке ядра отладчиком
  IWDG замораживается (`__HAL_DBGMCU_FREEZE_IWDG`).
- В лог при старте печатается причина сброса (`RCC_CSR`: POR/PIN/SW/IWDG/WWDG/LPWR),
  раз в 10 с — `[sup] up Ns bands ... scd ok/total heap ... sup_hw ...`.
  Стек `sup` не меньше 256 слов: `printf` на newlib съедает ~512 байт, на 128 словах
  задача переполняла стек, watchdog не кормился и плата ребутилась каждые ~10 с.
- HAL-тик — на **TIM3** (у C6 нет TIM4), потому что SysTick отдан планировщику FreeRTOS.
- Полоса отрисовки по умолчанию уходит блокирующим `HAL_SPI_Transmit()`.
  При `LCD_USE_DMA 1` включается **DMA1 Channel 3**: задача ждёт бинарный семафор
  из прерывания завершения (`HAL_SPI_TxCpltCallback`), ISR priority 5, при ошибке —
  `HAL_SPI_Abort()` и счётчик `g_lcd_spi_err`.
- Обмен с датчиком идёт через мьютекс `g_meas_mutex`.
- Дисплей **обязан уступать CPU**: в цикле стоит `vTaskDelay()`, а не `vTaskDelayUntil()`.
  Кадр рисуется ~57 мс, поэтому `vTaskDelayUntil(40)` никогда не блокируется и задача
  датчика (меньший приоритет) голодает — именно так SCD41 «не находился», хотя был подключён.
- Для отладки I2C есть `scd41_scan_bus()`: результат пишется в `g_i2c_scan[128]` и читается по SWD.
- Логи идут через `log_printf()`: статический буфер + `vsnprintf` и мьютекс, чтобы
  строки из разных задач не перемешивались; `printf()` в `main()` до старта
  планировщика уходит через `_write()`.
- Цвета — RGB565 с байтовым свапом (ESP32/STM32 little-endian, панель ждёт big-endian).

Память после сборки: **RAM 8.7 КБ из 10 КБ (85 %)**, **Flash 26.4 КБ из 32 КБ (80 %)**.

## Настройки в `include/board.h`

```c
#define LCD_GAP_Y 20      // 240x280 внутри 240x320: 20 или 0
#define LCD_INVERT_COLOR 1
#define LCD_SWAP_BYTES 1  // если цвета «попугайские» — 0
#define LCD_BAND_LINES 4  // полоса отрисовки, 1920 байт
```

## Диагностика

| Симптом | Что делать |
|---|---|
| Экран белый/чёрный | питание, BL, RST (PA2); проверьте `LCD_INVERT_COLOR` |
| Картинка сдвинута на 20 px | `LCD_GAP_Y` 20 ↔ 0 |
| Цвета неверные | `LCD_SWAP_BYTES` 1 ↔ 0 |
| Красный/синий перепутаны | в `lcd_st7789.c`: `MADCTL` 0x00 → 0x08 |
| Мусор/залипание экрана | ниже `LCD_SPI_PRESCALER` уже некуда (9 МГц) — укоротить провода, добавить 22–100 Ом в SCLK/MOSI |
| `[scd] sensor not found` | питание датчика, подтяжки 4.7 к, SDA/SCL на PB7/PB6 |
| Нет логов в консоли | PA9/PA10, скорость 115200, общий GND |
| Плата не прошивается | BOOT0/ST-Link, питание 3.3 В |
